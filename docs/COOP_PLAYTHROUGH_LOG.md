# Co-op playthrough log (main journey)

A continuous two-player run of the main story on one ROM build, driven by the
harness (`tools/coop_link_harness`), scenario files `journey_NN_*.txt`. Each
segment CONTINUEs the saves the previous segment wrote. No story flags, badge
grants, warps, stat boosts or forced wins in these segments; the only driver
aids are named in each file (for example `smart_moves`, which keeps the move
cursor on the strongest damaging move, and `grind`, which paces in grass and
fights until a battle count or an HP floor).

Players: player 0 **Kai** (boy), player 1 **Rosa** (girl). Checkpoint saves
live outside the repository (`/home/claude/journey/<segment>/p0.sav, p1.sav`
in the work environment); they are not committed.

## Run instructions update (2026-10-27)

From journey 33 on: combat assistance is allowed for efficient main-story traversal (never for progression), and grinding is no longer required. Assistance goes through `gCoopTestMailbox` (`src/coop_testhook.c`): inert in play, served only when the harness writes its magic value; it uses the game's own creation, experience, stat, moveset, healing and bag functions. Every use is a `TEST HELPER` line in the segment log. Badges, story flags, trainers and key items are never touched; every story step is still played.

Speed: the harness was measured, not just set faster. Field play already ran at about 9x real time; battles ran at about 1x because the driver resolved symbol names by scanning all ~220k symbols several times a frame (gdb samples: `symValue`, `symName`). With cached and address-sorted lookups, a Route 110 training cycle went from 380 s to 47 s (about 580 frames/s, ~10x real time); the Brawly segment above took 97 s. Emulation and the link are unchanged (every frame still runs on both cores in lockstep); the driver still advances on game states (callbacks, tasks, text, field control), not on wall-clock delays.
